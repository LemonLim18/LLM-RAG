## Current scope guard

Iteration 14 adds only real instruction-to-proposal computation for the active working document. It does not create/refresh planning sessions, accept or save edits automatically, write originals/inventory/knowledge, implement agents, or execute devices. Existing inline review and Ctrl+S remain the decision/persistence boundary. The paragraphs below retain their historical Iteration 12/13 verification evidence; the former absence of a production AI producer is resolved only by Iteration 14's bounded adapter.

Iteration 13 review boundary: one transient proposal per document, guarded by active editor identity, saved revision, buffer epoch and exact base text. Stage/accept/reject/manual review make no backend requests. Accept changes only the working buffer; explicit existing Ctrl+S persists it. Pending preview never overwrites accepted text. Uniform LF/CRLF, Unicode, empty text and preserved BOM are supported; changed BOM, mixed EOL and bare CR proposals are refused rather than silently normalized. Test-only proposal instrumentation is excluded from normal dev and production entry points. No real AI edit producer, proposal store or backend change.

Monaco read-only programmatic acceptance, empty-buffer EOL and new test selector/fixture issues were corrected before final verification. The existing bundle-size warning remains.

Capture and working creation are two operations, not a transaction; a retained original remains discoverable if creation fails. Browser timeouts do not cancel backend work.
