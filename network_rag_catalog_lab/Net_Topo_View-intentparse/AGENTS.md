## Engineering boundaries

- Preserve existing GUI, SQLite persistence, local simulation and normal-mode adapters.
- Reuse the existing V9 authoring store, schema compiler, template bindings, publication lifecycle and runtime retrieval. Do not create parallel catalogs, JSON files, compilers or operation recognizers.
- Schemas are generated by the system. Senior engineers define global parameters, category assignments, operation mappings/rules, and vendor/platform/version Jinja2 templates.
- Published knowledge alone feeds mutable runtime behavior. Do not let draft authoring changes affect the active runtime.
- Keep native CLI templates separate from Ansible wrapper playbooks.
- Do not weaken inventory, vendor/platform/version, target-resolution, policy, or validation checks to make a test pass.
- Do not automatically commit, publish a non-test release, change user data/active releases, delete data, or perform real SSH/deployment.
- Make minimal changes; preserve unrelated dirty worktree changes.

## Working style for a new iteration

First inspect the checkpoint, relevant existing changes, and prior targeted test results. Define one user-requested outcome, retain the above completed work, test incrementally in an isolated environment, update the checkpoint only with actual results, create a concise handover, and stop when the accepted scope is complete. Do not rerun broad passing suites without a relevant change.
