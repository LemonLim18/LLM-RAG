## Root causes and exact corrections

### Advisory intention was becoming execution

Before this continuation, engine.understand could enter investigation.contextual_route before semantic routing. Prior investigation domains or select_context.resolve_read then became executable readers. The no-reader advisory composer was attached only through the general Approach A experiment.

The original OFF FL-C1-2 actually invoked inventory.read and network.state despite the explicit no-read instruction. The ON variant failed an outcome association, lost useful advisory context and rejected future-oriented rationale as though it were a current observation.

Changes:

- request_contract.advisory_contract reuses the existing requested-outcome/speech-act representation for advice-only requests independently of the general experiment. No second intent object or planner is introduced.
- gateway_routing.advisory_route binds future checks before read planning and supplies an empty executable source plan.
- engine.understand applies that same boundary before investigation-history routing. Mixed present-read requests retain the ordinary workflow.
- gateway_references.resolve_read now has a server-only reference_only mode. It resolves names/pronouns without interpreting prospective or prohibited effect words as authority. Ordinary callers keep their existing behavior.
- The existing modal speech-act grammar recognizes asking for prospective evidence, as well as requesting/inspecting it; past recommendations and present reads remain negative controls.
- engine.resolve_references canonicalizes advisory device identity before composition. Owned prior goals, gaps and historical reader status receipts reach the model, without importing earlier assistant claims as network facts.
- advisory_answer retains the typed authorized-reader schema and never dispatches the proposed checks. An observational verifier is no longer applied to future rationale against an empty evidence packet. Suggestions and rationales are explicitly labelled uncertified, not observations or diagnoses.

Intermediate API results correctly executed zero readers but repeated a saved-configuration request that had already succeeded. Full-answer review did not count these as complete advice. Adding prior success/unavailable receipts addressed a real context gap: the final browser cases chose state/telemetry rather than simply repeating the saved read. Advice relevance and arbitrary rationale remain model-dependent; no universal advisory semantic validator is claimed.
